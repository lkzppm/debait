# Debait — guide for Claude Code sessions

A chat room where two people debate a motion while Deb, an AI referee, scores each message live, flags fallacies, and moves a meter between the two sides. Debaters can call the bot with `@deb` to validate a claim or web-search something. A UFRJ course task ("criar um chatbot sobre um tema próprio"), **presented in 15 minutes on Friday 2026-10-09**. Next.js on Vercel, Groq free tier. Repository: `lkzppm/debait` (the local folder is still named `Debate-ai`).

**Read `spec/README.md` first.** It indexes the knowledge base (idea, market research, architecture as built, judge design, UI, versions, roadmap).

## Where things stand

- Deployed on 2026-10-06: **https://debait-ufrj.vercel.app**, Upstash Redis and the Groq key configured; `main` is protected (pull request + green CI) and auto-deploys. Details and how it was done in `spec/05-stack-and-versions.md`.
- The scaffold of the whole app was built on 2026-10-06. `spec/06-roadmap.md` has the table of what was run and what was not: in short, everything works on the **mock judge + memory store**; the **Groq engine, the Upstash driver and a deployment have never been run**.

- Lucas is refining the interface and the agent logic himself. Do not redesign screens or prompts unasked.

## Commands

```
pnpm dev                                    # no configuration needed: memory store + mock judge
pnpm lint && pnpm typecheck && pnpm build   # must be green (CI enforces)
pnpm judge '<message>'                      # one judgement in the terminal
pnpm mention '<question>' --reply           # one @deb call in the terminal
pnpm exec vgpu check src/components/cubes/cubes.wgsl
```

`/create` and `/admin` use the password `admin` in development when `ADMIN_PASSWORD` is unset.

## Rules

- The model observes, the code scores: points, the meter and the winner are computed in `src/lib/debate/`, never taken from model output. Whatever an engine returns goes through `normalizeJudgement` / `normalizeReply` before it enters the log.
- A room is an append-only event log, and `reduce()` in `src/lib/debate/reducer.ts` is the only place state is derived, on the server and in the browser. Add a feature by adding an event and a reducer case, not by keeping state elsewhere. The one exception is presence (who is typing, 2026-10-08): it expires in seconds, so it lives in a self-expiring key and travels as a `typing` frame on the SSE stream, never in the log.
- The meter means "who is arguing better", never "who is right". Keep that wording in UI and docs.
- Debater text is untrusted data in every prompt, mentions included.
- Every model call goes through `checkBudget` and `addUsage` (`src/lib/usage.ts`). The free tier is 8,000 tokens/min and 200,000 tokens/day per model: use the mock (`JUDGE_ENGINE=mock`) for UI work, be frugal when testing against Groq, and spend nothing on Friday.
- The mock judge is for building the interface. Its scores mean nothing; never present them as the judge, and keep its labels on screen.
- Debates are created only on `/create`, behind the admin password; `/join` enters one by code; `/admin` is the panel (spending, stop, delete).
- The whole codebase is English (code, comments, commits, docs). The UI and the prompts are bilingual, Portuguese by default, English by a switch: every visible string lives in `src/i18n/` (`en.tsx` is the schema, `pt.tsx` must match it), never inline in a component. Events carry ids and numbers, not translated labels. No em dash in anything the visitor reads.
- Project and bot names come from `src/lib/brand.ts`, never hard-coded.
- `src/components/ui/**` is generated by the shadcn CLI: re-add, do not hand-edit.
- Next.js 16 and AI SDK 7 differ from training data: read `node_modules/next/dist/docs/` and the `ai` `.d.ts` files before using an API from memory. TypeScript 5 and ESLint 9 are pinned on purpose.
- The look follows cognee.ai (Lucas, 2026-10-06): a thin pixel grid, cubes rendered with vgpu, Inter at normal and medium weight (no `font-light`), square cards and square buttons with icons (pills only for sliders, Lucas 2026-10-07), a plain square top bar (`site/nav.tsx`); side A is blue, side B is red (Lucas, 2026-10-07, chosen over neon purple vs aqua knowing that red vs blue can read as political parties in Brazil). `spec/04-ui-design.md` has the vocabulary (eyebrow, marker, mosaic, crooked flags). Red is a side, so fallacy flags and errors are magenta (`--destructive`), never red, and no side colour ever means "good" or "bad".
- Two themes, paper and night (`.dark` on `<html>`, `src/lib/use-theme.ts`). Colours come from the tokens in `src/app/globals.css`, never a hex value in a component; the cubes shader parses `--side-a`, `--side-b`, `--background` and `--foreground` as 6-digit hex.
- The landing page follows GraphMan's: the name, one sentence, and animated figures that explain. No marketing phrases; a figure's numbers come from the scoring code.
- Branches `main` ← `dev` ← `feat/*`; commit with `/commit`, integrate with `/merge`; never push to `main` directly.
